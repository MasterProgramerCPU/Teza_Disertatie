\chapter{Configurații Kubernetes}
\label{app:kubernetes}

Această anexă include manifestele declarative pentru rularea sistemului
pe un cluster Kubernetes. Toate resursele sunt aplicate în namespace-ul
\texttt{epimodel} și urmează structura arhitecturală descrisă în
capitolul~\ref{ch:arhitectura}: API stateless, frontend servit prin Nginx,
runnere scalabile independent, Redis pentru coada de mesaje și YugabyteDB
pentru persistență (3~master + 3~tserver, RF=3).

Manifestele se află în directorul \texttt{code/k8s/} al repository-ului și
sunt organizate cu prefixe numerice pentru aplicare secvențială.
\Cref{tab:k8s_manifeste} sintetizează conținutul directorului.

\section*{YugabyteDB --- valori Helm}

YugabyteDB rulează ca două \texttt{StatefulSet}-uri (\texttt{yb-master}
și \texttt{yb-tserver}) cu câte 3 replici, generate de Helm chart-ul
oficial. Fișierul de \texttt{values} suprascrie sizing-ul implicit
pentru a se potrivi resurselor cluster-ului (workeri 4~vCPU / 8~GiB)
și dezactivează componentele neutilizate (\texttt{yugabytedUi},
\texttt{enableLoadBalancer}).

\lstinputlisting[language=bash, caption={\texttt{10-yugabyte-values.yaml} --- Valorile Helm pentru YugabyteDB.}]{../code/k8s/10-yugabyte-values.yaml}

\section*{Service de acces la YugabyteDB}

Chart-ul oficial generează două Service-uri \emph{headless}
(\texttt{yb-masters} și \texttt{yb-tservers}) pentru DNS-ul intern
necesar protocolului Raft, dar nu un Service \texttt{ClusterIP}
clasic pe care îl pot folosi consumatorii YSQL. Acest Service este
adăugat printr-un manifest separat.

\lstinputlisting[language=bash, caption={\texttt{12-yugabyte-tserver-service.yaml} --- \texttt{ClusterIP} \texttt{yb-tserver-service} (port 5433, YSQL).}]{../code/k8s/12-yugabyte-tserver-service.yaml}

\section*{Redis}

Redis este deployat ca \texttt{Deployment} cu o singură replică și volum
efemer (\texttt{emptyDir}). Cozile de mesaje nu sunt persistente între
restarturi, ceea ce este acceptabil pentru job-uri de simulare care
durează secunde sau minute. Pentru retenție durabilă, structura poate
fi convertită într-un \texttt{StatefulSet} cu \texttt{PersistentVolumeClaim}
fără modificări la nivelul aplicației.

\lstinputlisting[language=bash, caption={\texttt{20-redis.yaml} --- Redis cu volum efemer.}]{../code/k8s/20-redis.yaml}

\section*{Job-ul de migrare}

Migrațiile SQL sunt aplicate printr-un \texttt{Job} care folosește
clientul \texttt{psql} (în loc de \texttt{golang-migrate}) pentru a
evita dependența de \emph{advisory locks} PostgreSQL, pe care YugabyteDB
nu le implementează încă. Job-ul iterează fișierele \texttt{*.up.sql}
în ordine alfabetică și le aplică cu \texttt{ON\_ERROR\_STOP=1}.

\lstinputlisting[language=bash, caption={\texttt{30-migrate-job.yaml} --- Job care aplică migrațiile prin \texttt{psql}.}]{../code/k8s/30-migrate-job.yaml}

\section*{API Go}

API-ul rulează ca \texttt{Deployment} cu două replici pentru toleranță
la pierderea unui pod. Configurația non-sensibilă provine din
\texttt{ConfigMap}, iar parolele și secretele din \texttt{Secret}.
Probele HTTP pe \texttt{/api/health} verifică atât pod-ul, cât și
conectivitatea efectivă către baza de date și Redis.

\lstinputlisting[language=bash, caption={\texttt{40-api.yaml} --- Deployment și Service pentru API-ul Go.}]{../code/k8s/40-api.yaml}

\section*{Runner Julia}

Runner-ul Julia este \texttt{Deployment}-ul cu cele mai generoase limite
de resurse (512~MiB request, 2~GiB limit) din cauza costului inițial de
încărcare al pachetelor \texttt{DifferentialEquations.jl}. Runner-ele
R și Python au structuri identice, dar cu limite mai mici.

\lstinputlisting[language=bash, caption={\texttt{52-runner-julia.yaml} --- Deployment pentru runner-ul Julia.}]{../code/k8s/52-runner-julia.yaml}

\section*{Ingress de rutare}

Ingress-ul nginx rutează cererile externe către cele două servicii
vizibile public: API-ul Go pentru cererile sub prefixul \texttt{/api}
și frontend-ul Vue.js pentru restul. Hostname-ul implicit
(\texttt{epimodel.local}) este destinat utilizării prin \texttt{/etc/hosts}
local; într-un deployment cu DNS public, se înlocuiește cu un FQDN
real și se adaugă o secțiune \texttt{tls:} cu certificate gestionate
prin \texttt{cert-manager}.

\lstinputlisting[language=bash, caption={\texttt{70-ingress.yaml} --- Ingress nginx pentru rutare HTTP.}]{../code/k8s/70-ingress.yaml}
